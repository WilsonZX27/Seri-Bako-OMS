# v9.1 Compliance & Staff Operations Preview

## Reuse and gap matrix

| Capability | Existing OMS authority reused | Preview gap filled | Boundary |
|---|---|---|---|
| Identity | `auth.users` -> `staffs.auth_user_id` | None; compliance records reference `staffs.id` | No second login or employee table |
| Outlet scope | `branches`, `staff_branches`, `can_access_company_branch` | Subject and owner links | RLS, not UI-only filtering |
| Roles | `roles`, `role_permissions`, staff overrides | Dedicated People Operations role and five compliance permissions | Manager manages staff and outlet status; Finance has no implicit compliance access |
| Attachments | `attachments`, private storage, signed URL API | Compliance link and sensitive-file re-authorization | Non-HR cannot open health files; sensitive free text/reference metadata is redacted on write |
| Notifications | `notifications` | Reminder-day configuration stored | Scheduled delivery is post-Preview work |
| Audit | `audit_logs`, `activity_logs` | Immutable safe compliance history, including file open/download | Medical content is not copied into history |
| AMS assets | Existing external system identity | Optional `asset_external_ref` | Reference only; no AMS writes or merge |

## Data model

- `compliance_types`: company-owned type, subject kind, sensitivity and default 90/60/30/7 reminder days.
- `compliance_records`: one Outlet, Staff or referenced Asset subject; issue/expiry, owner, review state and optional canonical attachment.
- `compliance_record_history`: safe create/update/submit/review/renewal and sensitive-file access events.

Derived operational state is `Missing document`, `Pending review`, `Expired`, `7/30/60/90 days`, or `Valid`. Review state remains independent so approval history is not overwritten by expiry calculation.

## Roadmap boundary

Payroll, leave, recruitment, algorithmic performance scoring and inferred outlet-health scoring are excluded. A later factual staff-operations slice may reuse immutable attendance, checklist or training records only after their source authority, retention and role scope are approved.
