# Seri Bako OMS — Architectural Diagnostic Log

**Scope:** production-grade UX, operational safety, role routing, application security, and automated verification.
**Status:** active; this log records verified work only. It is not a release approval.

## Operating standard

- Preserve the existing OMS business flows unless a safety or usability defect requires a targeted change.
- One design system across phone, tablet, and desktop: shared tokens, controls, document workspace, table behavior, and workflow language.
- Phone is a focused task surface; tablet uses the extra width for readable operational context; desktop supports dense review without hiding primary work in a drawer.
- No release, production deployment, or git push occurs from this audit without explicit approval.

## First core module: Auth, session routing, and Dashboard

### Required behavior

1. Validate and normalize sign-in, password, and profile input on the server.
2. Authenticate, then resolve a linked staff profile and current effective role before routing into an operational workspace.
3. Redirect disabled, unassigned, and must-change-password accounts to a clear safe state instead of allowing a partial workspace.
4. Render the role-specific Dashboard with actions visible at the current breakpoint; no primary action is drawer-only on tablet or desktop.
5. Expose a resilient error boundary that preserves saved data and offers retry, back, and Dashboard recovery.
6. Prove the route at six viewport bands and across six local role fixtures, with no page console errors and no horizontal overflow on authentication screens.

### Current implementation evidence

- `src/server/auth/auth-input.ts` uses Zod validation/normalisation for all authentication inputs.
- `src/server/actions/auth.ts` resolves profile, password-state, role assignment, and permitted landing route server-side.
- `src/app/(app)/layout.tsx` checks active staff state before rendering the workspace shell.
- `src/app/(app)/dashboard/page.tsx` handles partial Dashboard query failures without a blank screen.
- `src/app/(app)/error.tsx` gives an explicit recovery path and does not expose raw server errors.
- `tests/e2e/security-responsive-core.spec.js` and its local fixture generate a matrix for six role fixtures across 320px, 390px, portrait/landscape tablet, desktop, and wide desktop. It asserts the expected shell, containment, responsive navigation, and zero browser-console errors when a disposable local Supabase/browser environment is available.
