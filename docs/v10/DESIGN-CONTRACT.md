# Accepted OMS design contract for v10 preparation

Baseline owner: existing `DESIGN.md`, `src/app/design-system-v2.css`, shared Workspace/List/Document shells. This freezes accepted patterns for audit; it does not generate a replacement design system.

1. One primary page identity, meaningful current status and discoverable next action. Use the system's OMS location/name authority. Do not silently turn an unmapped imported label into a canonical name.
2. Reuse the existing component before adding a new variant. Fix the common owner of geometry or content. Avoid stronger `!important` patches and page-specific copies of shared controls. Match source/data meaning across list/detail/notifications.
3. Preserve accepted compact scales: PR phone metadata 11px; asset checklist copy 12px; fine-pointer desktop controls 36px; touch targets 44px. Shared compact search/filter controls with an established 44px contract keep that contract. No blanket shrinking or enlarging. Contrast, readable text and zoom/reflow require rendered checks, not a CSS pass claim.
4. Phone actions remain reachable above the bottom navigation. Tablet right panels remain beside the canvas where the existing accepted split applies; do not collapse a requested persistent panel into More actions. Prevent overlays, menus and sticky bands from obscuring fields/actions.
5. Use one visible search action, clear active filters/reset, equal geometry and the shared pagination component. Preserve filters when selecting/changing an item. Keep the accepted ten-row asset maintenance queues; other list page sizes need a named owner rather than a global replacement.
6. One concise explanation where it helps. Remove repeated Needs confirmation / Needs entry copy when the meaningful status already says Pending. Do not remove essential validation, unsaved-work, financial, irreversible-action or uncertain-outcome instructions. Detail can be progressively disclosed without making the next action hard to find.
7. Unknown, pending and explicit zero differ. Never render unavailable data as zero. A draft quantity is not a confirmed final quantity. Author/submitter/updater must retain their actual meanings. Never change underlying dates/records to make screenshots look correct.
8. Every form supports labels, keyboard order, visible focus, error association and a recoverable state. Dialog focus is contained and restored. 403 means access denied, not expired login. Login return paths are same-origin/relative; submissions are not silently replayed.
9. Beginner test: from the starting page, a user can name the task, find the next action, enter required values, understand success versus uncertainty, and recover from a validation/session error without specialist explanation. Measure actual completion/friction; do not equate fewer labels with easier use.
10. Changes stay small and reviewable: requirement → owning source → reproduction → targeted change → regression → rendered comparison. No speculative abstraction, global restyle or page-wide redesign from a local annotation.

Audit widths: primary 390/820/1440; boundaries 389/390/391, 639/640, 767/768, 1023/1024, 1279/1280, 1535/1536; relevant landscape 820×390. Use the same data/state and source SHA for comparison. Screenshot capture must come from the actual target; Mock and old screenshots cannot establish current Preview acceptance.
